# HTTP API

The engine serves its UI and this API on `http://127.0.0.1:8765` (`--port` or `HAUL_PORT`), on the loopback interface only. Browser integrations (a bookmarklet, a future extension) and scripts can use it.

Any web page you visit can send requests to loopback addresses, so the server guards itself:

- Every request must carry a `Host` of `127.0.0.1:<port>`, `localhost:<port>` or `[::1]:<port>`, which defeats DNS rebinding.
- A request that changes anything is refused when it carries an `Origin` other than the server's own. Browsers send `Origin` on every POST; scripts that send none are allowed.
- Pages are served with a Content Security Policy that forbids framing, so no other page can overlay the UI to steer clicks.

Bodies are JSON. Errors come back as `{"error": "…"}` with a 4xx or 5xx status.

## State

| Method and path   | Does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /api/state`  | The whole state: `items`, `archives`, `wrappers`, `wrapper_cards`, `hosts`, `counts`, `paused`, `speed` (bytes/s), `max_total`, `rate` (bytes/s cap, 0 = none), `proxy`, `pool`, `pool_summary`, `slots_max`, `theme`, `watch_clipboard`, `recycle_on_remove`, `skip_add_dialog`, `bin` (what the system calls its Recycle Bin), `config_version` (moves when a setting changes), `config_error` (why the settings file is not in effect), `download_dir`, `data_dir`, `config_file`, `desktop`, `version`, `update` (a newer Haul on GitHub: `version`, `notes`, `page`, and `installable` when the desktop app can install it itself; `null` otherwise). Account secrets are never part of it. |
| `GET /api/events` | Server-sent events: a `state` event with the same JSON right away, after every change (bursts merged) and at least once a second.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

An item has `id`, `name`, `package`, `status` (`checking`, `queued`, `resolving`, `downloading`, `waiting`, `paused`, `captcha`, `done`, `error`), `error`, `size` and `done` (bytes, 0 when unknown), `speed`, `percent` (from external downloaders), `host`, `mirrors` (host names), `wait` (seconds), `retry_in` (seconds until a failed item is tried again on its own, 0 when never), `open_urls` (pages that need a person), `path` (where a finished file went), `existing` (true when the file was in the download folder already, so nothing was downloaded), `verifying` (`waiting` or `comparing` while a file on disk is compared with the host's checksum, empty otherwise) and `source` (the id of the wrapper it came from, or `null`), `extract` (for a part of an archive in parts: `waiting`, `extracting`, `done`, `password` when it is encrypted and no password Haul has fits, or `failed`, once it is to be unpacked; empty before), `extract_error` (why unpacking failed) and `extract_progress` (0 to 1 while it is unpacked, `null` otherwise). A wrapper's files are added `paused` with nothing `done`: not started. What follows from the state comes worked out, so a view only lays it out: `list` (the list it is in beside All downloads: `active`, `attention`, `failed`, `paused` or `done`), `not_started` (paused before any byte came), `shown_host` (the host it downloads from, or before it starts the one it would try first), `preferred_host` (that host is a preferred one), `other_hosts` (how many other hosts that are on could take over), `error_shown` (`error` without `shown_host`'s name in front), `commands` (what its buttons do: `pause`, `start`, `resume`, `retry`, `reveal`, `recycle`, `remove`, `remove_partial`, which deletes a partial file and asks twice, and `clear`), `archive` (the key of the archive in parts it is one of, or `null`) and `source_name` (the name of the wrapper it came from).

An archive in parts (`archives`) is two parts or more of one archive in one package, as their names show (see [Using Haul](usage.md#archives)): `key`, `name` (`name.rar`, `name.7z`, `name.zip`, or for pieces of any file the file's), `ids` (its parts, in part order), `missing` (parts the names show are missing, by name), `status` (what needs attention first among the parts), `complete`, `size`, `done`, `speed`, `share` (how far the parts have come, 0 to 1), `tally` (`{"done", "downloading", "waiting", "not_started", "paused", "captcha", "failed"}`: its parts counted by state), `hosts` (those its parts are shown under), `other_hosts`, `package`, `source`, `source_name`, `extract`, `extract_error`, `extract_progress` and `commands` (`pause`, `start`, `resume` and `retry`, which act on the parts whose own commands include them, and `extract`, `extract_again` and `password`, which asks for the archive's password, on the archive).

`counts` holds what the navigation pane and the status bar show: `all`, `active`, `attention`, `failed`, `paused` and `done` (items per list), `downloading`, `waiting`, `held` (paused, and the pause holds back something that would run), `wrappers` (wrapper cards) and `wrappers_alert` (`critical` when one failed, `attention` when one waits for a person, empty otherwise).

A wrapper (fileguard.cc, filecrypt.cc, a `.dlc` link) is no item: it has `id`, `url` (the link as added), `host`, `title` (the page's name for what it holds, once unwrapped), `package`, `status` (`unwrapping`, `waiting`, `passing` while the desktop app passes its page's check by itself, `captcha` when a person has to pass its gate, `paused`, `error` or `done` once unwrapped), `error`, `wait`, `retry_in`, `open_urls`, `found` (`{"files", "links"}` once unwrapped, `null` before) and `source` (the wrapper it was found on, such as the release's page a paste was linked from, or `null`). A release's page on a site Haul has no code for, and a paste, are wrappers too. Its id takes the item actions that apply to it: `retry`, `retry_manual`, `browse` and `direct`. `wrapper_cards` holds them as the Wrappers view shows them, the wrappers of one release (unwrapped under the same name, or found on the same page) on one card, its state that of the one needing attention first: `key`, `ids` (the first one's state is the card's), `name`, `urls`, `host`, `hosts` (the hosts their links are on), `status`, `error_shown`, `wait`, `retry_in`, `open_urls`, `found`, `files` (the files they added, counted once) and `tally`.

A host has `name`, `limit`, `active`, `speed` (bytes/s per file), `ok`, `fails`, `bytes`, `blocked` (answered 403/451 through the proxy), `route`, `cooldown` (seconds), `folder` (its subfolder of the download folder, empty for none), `preferred` (its place among the preferred hosts, 0 first, or `null`) and `cap` (the most downloads it takes at once, learned when it refused one more, or `null`), and as the Hosts view shows it: `group` (`preferred`, `other` or `off`), `fastest`, `slots` (downloads it runs at once: `limit`, or `cap` when lower; at most `slots_max`), `limited` (a limit is set or was learned) and `movable` (it can trade places with another preferred host). The list holds every host Haul has reached and every preferred host, reached or not, in the order downloads pick them: preferred, then fastest.

`pool` counts the addresses in use (`line`, `proxies`, `vpn`, and `on`, the switch for proxies and VPN together); `pool_summary` says it in words: `label` (`Line + 2 proxies + 5 NordVPN`, or `Line only`), `configured` (a proxy or a VPN service is set up), `sources` (each with `name`, `status`, `key`, the setting its switch flips or `null`, `on`, `problem` when it is on yet adds nothing, and `label`, its switch's name when not its own) and `why` (why the pool is only the line although proxies or VPN are on, or `null`).

## Adding

| Method and path            | Body                            | Does                                                                                                                                                                                                                                                            |
| -------------------------- | ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/add`            | `{"text": "…", "package": "…"}` | Adds every http(s) link in `text`; `package` is an optional subfolder. Answers `{"added", "merged", "duplicates", "invalid", "wrappers"}`: wrapper links count apart, and a second link to the same wrapper (another of a fileguard.cc vault's) as a duplicate. |
| `POST /api/container`      | multipart, one or more files    | Imports `.dlc` containers and text files with links. Same answer as `/api/add`.                                                                                                                                                                                 |
| `POST /api/container/read` | multipart, one or more files    | The links in them, without adding anything: `{"links": [...], "package"}`, `package` being the one they all share (empty when they differ).                                                                                                                     |

The UI also opens its Add dialog, filled in, at `/#/add/<url-encoded links>`; nothing is added until the user confirms.

## Items

| Method and path                 | Body                                        | Does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------- | ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/item/{id}/{action}`  |                                             | `pause`, `resume`, `retry` (all mirrors again), `retry_manual` (ask the hosts that wanted a person again), `remove` (also deletes its partial file; with `recycle_on_remove` on, a finished file goes to the Recycle Bin first, and when that fails the item stays and the answer is a 500 saying why). `extract` (unpacks the archive in parts the item is one of; 409 saying why when it is not one, a part is missing from the list or not downloaded yet). `POST /api/item/{id}/extract` also takes `{"password": "…"}`, kept with the archive and tried first. A finished item only takes `remove` and `extract`; the others leave it as it is. |
| `POST /api/item/{id}/direct`    | `{"url": "…", "headers": {…}, "name": "…"}` | Downloads this item from a link the user supplies, with optional request headers (cookies, referer) and a name for rows that have none. A finished item answers 400.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `POST /api/item/{id}/browse`    | `{"user_agent": "…"}`                       | Desktop app only (501 elsewhere): opens the item's page in the in-app browser, which hands the download back with the page's cookies and this user agent.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `POST /api/download-from`       | `{"ids": ["…"], "host": "a.example"}`       | Has these items download from `host` while it has their file, the other hosts standing by; `"host": null` goes back to the usual order. An item without a link on `host` is left as it is. Answers `{"changed": n}`. Items in the state carry the choice as `download_from`.                                                                                                                                                                                                                                                                                                                                                                         |
| `POST /api/wrapper/{id}/start`  |                                             | Starts the files the wrapper added that wait (`paused`). Answers `{"started": n}`; 404 when there is no such wrapper.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `POST /api/wrapper/{id}/remove` |                                             | Takes the wrapper off the list, with its files that never started; those that did stay.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `POST /api/item/{id}/reveal`    |                                             | Shows the finished file in the file manager.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

## Hosts and settings

| Method and path                               | Body                                    | Does                                                                                                                                                                                                                                            |
| --------------------------------------------- | --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/host/{name}/limit/{n}`             |                                         | Files downloaded from this host at once (1 to 32); saved under `[limits]` in `config.toml`.                                                                                                                                                     |
| `POST /api/host/{name}/folder`                | `{"folder": "…"}`                       | The subfolder of the download folder for this host's files, saved under `[folders]` in `config.toml`; empty puts them back in the download folder itself.                                                                                       |
| `POST /api/host/{name}/preferred`             | `{"preferred": true}`                   | Adds the host to the end of `preferred_hosts` in `config.toml`, or takes it out; a host already preferred keeps its place.                                                                                                                      |
| `POST /api/preferred-hosts`                   | `{"hosts": ["a.example", "b.example"]}` | Sets the whole of `preferred_hosts` in `config.toml`, in this order: how the Hosts view reorders it. An empty list means no preference (`[]` is written, not the default). A blank name or a host listed twice answers 400 and changes nothing. |
| `POST /api/host/{name}/route/{direct\|proxy}` |                                         | The user's route choice for a host when a proxy is configured; saved under `[routes]` in `config.toml`.                                                                                                                                         |
| `POST /api/global/{action}`                   |                                         | `pause` (also pauses running transfers), `resume`, `retry_failed`, `clear_done`, `clear_failed` (takes every failed download off the list, with its partial file).                                                                              |
| `POST /api/update/check`                      |                                         | Asks GitHub for a newer Haul now; `update` in the state says what it found.                                                                                                                                                                     |
| `POST /api/update/install`                    |                                         | Desktop app: downloads the newer Haul, checks it against its `SHA256SUMS`, runs its installer over this version and closes; it opens again when installed.                                                                                      |
| `POST /api/open/{downloads\|data\|config}`    |                                         | Opens the download folder, the data folder, or `config.toml` (created from a commented template when missing).                                                                                                                                  |

## Settings

Settings use the names of `config.toml`; each change is checked, written to the file and applied at once.

| Method and path                        | Body                                                     | Does                                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/settings`                    |                                                          | Every setting, account secrets included, plus `from_env` (keys an environment variable sets, which cannot change here), `download_dir_fixed`, `config_file` and `error`.                                                                                                                                                                     |
| `POST /api/settings`                   | `{"max_total": 8, "theme": "dark", "1fichier_key": "…"}` | Any subset of the top-level keys in [Configuration](configuration.md#configtoml) except `preferred_hosts`, which `POST /api/host/{name}/preferred` and `POST /api/preferred-hosts` set. An empty text removes the key, which brings back its default. Answers 400 with the reason when a value is not accepted.                              |
| `GET /api/diagnostics`                 |                                                          | The diagnostics report, as a file to save (`haul-diagnostics-<time>.json`): version and system, the settings with account keys reduced to whether they are set and the proxy without its credentials, every download and wrapper with its links (without their `#` part), state and error, the hosts, and the end of the desktop app's logs. |
| `POST /api/diagnostics/save`           |                                                          | Desktop app only (501 elsewhere): saves that report where the user picks in the system's dialog. Answers `{"saved": path}` or `{"cancelled": true}`.                                                                                                                                                                                         |
| `POST /api/settings/download-dir/pick` |                                                          | Desktop app only (501 elsewhere): asks for a folder in the system's dialog and moves the downloads there, unfinished ones included. Answers `{"cancelled": true}` when the user cancels.                                                                                                                                                     |
