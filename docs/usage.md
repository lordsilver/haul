# Using Haul

## Adding links

Paste anywhere in the window (Ctrl+V), use **Add links**, drop links or `.dlc` / `.txt` files on the window, or pass them on the command line: `Haul.exe <link or file>…`. A second launch hands its links to the running app. Each way fills the Add dialog, so nothing downloads until you click **Add**; **Settings › Add dropped links and files right away** skips the dialog for dropped and opened ones.

From any page, this bookmarklet opens Haul's Add dialog with the page you are on (adding still takes your click):

```text
javascript:location.href='http://127.0.0.1:8765/#/add/'+encodeURIComponent(location.href)
```

With clipboard watching on (desktop app), links you copy anywhere are added when they point at a supported host, a file, a wrapper, a paste (zpaste.net, paste2.org…) or a release's post on a release site (elamigosgames.net, gload.to): copying a release's page is enough to bring in its files.

## Needs you

A host page requiring browser interaction parks its download under **Needs you**, and Haul comes to you: a count in the status bar, and a click on the desktop notification that lands on the waiting list — with a single download waiting, straight on its page.

In the desktop app, **Open here** opens the page in Haul's own browser window: complete the page's steps and press the host's download button, and Haul takes the download over (with the page's cookies, through your proxy if the host uses it). The window keeps to the host's site: when a click lets an ad send the page elsewhere, the window comes straight back, and that site's pages are not loaded again while Haul runs, and a page the host opens in a new window loads in the same one; pop-ups stay closed, and a layer an ad lays over the page to catch your first click is taken off it (a captcha's is left). A host that really moves you to another site gets there after the window has come back three times within half a minute. A release's page or a paste behind Cloudflare's check needs nothing from you in the desktop app: it is passed out of sight (see [Wrappers](#wrappers)), and only a check that wants a box ticked comes forward. With **Open here**, follow the page to the host you want (a link meant for a new window opens in this one): as soon as it shows links Haul can use, the page becomes a wrapper of them and the window closes. Anywhere else, **Open page** and **Paste link** do the same by hand; with one download waiting, Ctrl+V of its final link anywhere in Haul gives it to that download.

## Hosts

The **Hosts** view is where you choose which hosts Haul uses and in what order. It lists each host your downloads have links on, plus the ones you starred or switched off, in three groups. **Preferred, in order** comes first: a file on several hosts downloads from the first of these that has it (pixeldrain.com is starred from the start); star a host to add it at the end, and drag it by its grip, or use its arrows, to reorder. **Other hosts** are used when no preferred host has the file, the fastest first. A file whose page the desktop app passes by itself (vikingfile, gofile) waits for its turn in the browser rather than go to a host Haul has no code for, or one measured slower; its other hosts are used once the page wants you. Downloads with data on disk start before new ones, the nearest to done first. **Off** hosts are never used: switch a host off and its links are left alone, a file whose links are all on hosts that are off fails saying so, and switching one back on starts that file again. A host that gives Haul no file without an account (gofile, rapidgator and nitroflare need a premium one) is off too until you set it: it shows _Needs an account_ and a **Set account** button that opens its fields in the card, and setting the account starts the files that waited for it. Any host that takes an account (1fichier, pixeldrain, gofile, rapidgator, nitroflare) has a key button that opens its fields in its card, green once set; one with no links in the list yet is under **Accounts** at the end, where **Add an account** adds it. Each host also shows its speed, the folder its files go to (a subfolder of the download folder) and the proxy route. A host that refused more downloads at once shows _Takes N at a time_ and its slot buttons; for any other, the gauge button shows them, to limit how many files download from it at once. A host that looks blocked through the proxy offers **Allow direct**, which needs a second click because it reveals your real IP address to that host. In the lists, a row names the host it downloads from, starred when it is a preferred one and pinned when you picked it, and how many other hosts could take over. On a file with several hosts, click that host to choose it under **Download from**: one host for this file (for an archive, all its parts), or **Automatic** to follow the order above. With rows selected, **Download from** in the bar does the same for all of them, each taking the host if it has it.

The **Connections** page gathers what downloads go out through, in three groups: **Your line** (a new address from the router), **Proxies** and **VPN services**. They are one pool of addresses, not alternatives: proxies and VPN servers are used together, and your line can be one more of them. Each source has its own switch (**Your line in the pool**, **Use the proxies**, NordVPN's), which leaves its settings in place, and the status bar shows the pool in use (_Line + 2 proxies + 5 NordVPN_) with one switch for proxies and VPN together: off, every download uses your line. **Proxies** takes one proxy, and under **More proxies** as many more as you like, one per line: a VPN subscription's SOCKS5 servers (NordVPN offers some), local ports of a WireGuard-to-SOCKS5 tool, a bought list. Each download takes the proxy with the fewest downloads from its host and keeps it until it ends, so a host's limits per address (downloads at once, daily quotas, waits) apply to each proxy: three proxies get pixeldrain's five downloads at once three times over. **Your line in the pool** adds your own line as one more address, and **New connection for every download** suits a proxy that gives each connection another address. pixeldrain says how much it still allows an address at full speed today (6 GB); **Hosts** shows it, and downloads go through the addresses that still have some first.

**Your line** gets your own line a new public address from the router, which usually comes with a fresh allowance at every host. Haul finds the router on your network by itself (a FRITZ!Box among others) and shows it; **Get a new IP** asks first, saying how many downloads pause, then has it redial and reports the new address. A new address counts only when the internet sees it: Haul asks a public echo service (api.ipify.org) through your line before and after, since a router can report a new address of its own behind a carrier's shared one that stays the same. With **Get a new IP on its own**, Haul does it when a host has slowed your address for the day or asked it to wait a long while, and no proxy can take over, at most every ten minutes; downloads on your line stop for the redial and go on from where they were. It is all one **Router** card. Until a redial can work, both stay off and the card says what is missing, and nothing is stopped for a redial that cannot work; one that fails is shown on the card and as a notification. Under **How**, **Router** asks the router over UPnP, or with its login where it redials only with one: a FRITZ!Box always does (FRITZ!OS refuses the redial over UPnP and allows it over TR-064, which **Home Network › Network › Network Settings › Allow access for applications** switches on); its user is the one under **System › FRITZ!Box Users**, such as the `fritz1234` it creates for a box with a password only, and **My own command** runs a command of yours instead, for any other router or a VPN app (choosing **Router** again clears it). A line that comes back with the same address keeps it (DS-Lite and shared-address lines do), and Haul then stops trying on its own.

**VPN services** turns a VPN subscription's servers into proxies without typing their addresses. For NordVPN, enter its service credentials (Nord Account › NordVPN › manual setup, not the account's login), how many servers to use and, if you like, which countries: Haul reads NordVPN's list of SOCKS5 servers (67 in the Netherlands, Sweden and the United States when this was written), takes the least loaded ones, checks each through itself (the credentials are taken, the address downloads will come from, and that NordVPN calls the connection protected), adds them to the proxies, and refreshes the pick every hour. A server that does not answer gives way to the next least busy one. **Servers** lists those in use with their addresses, and **Check again** fetches the list and checks them anew. Credentials NordVPN turns away are said there; the servers stay in the pool, so downloads meant for the VPN wait rather than leave through your own line.

## Wrappers

A wrapper link (fileguard.cc, filecrypt.cc, a `.dlc` link) is unwrapped as soon as it is added, and **Wrappers** shows each one: unwrapping, how many files it found from how many links, waiting for you (a filecrypt.cc container behind a password, or one that turned Haul's answer away: **Open here** in the desktop app, or open the page and paste the `.dlc` link it offers), or failed and why; a release's wrappers (often one per host) share one card, which names the hosts their links are on and starts or removes them together; a wrapper still unwrapping, waiting for you or failed keeps a card of its own. Wrappers that finish unwrapping while their toast shows join it rather than raising another. Its files appear in the list **Not started**; start one with its ▶, an archive's parts with the group's ▶, or all of them with **Start all**. **Remove** on a wrapper takes the files that never started with it, after a second click. More in [Containers and wrappers](containers.md#wrapper-pages).

A release's page on a site Haul has no code for, and a paste (zpaste.net, paste2.org, pastebin.com and the like), are wrappers too: the page is read for its links to hosts Haul knows, wrappers and pastes, and a paste for every link it lists. A page behind Cloudflare's check is passed out of sight in the desktop app first. The pastes a release's page links show on the page's card, which counts them with it and says what still goes on (a paste being opened, or one that wants a box ticked: **Open here**), so one release is one card, and its files are in the list, not started, the same file on several hosts as one download.

## Selecting and removing

Tick a row's checkbox (it shows when you point at the row) to start a selection; once something is selected, a click anywhere on a row adds or drops it (Ctrl+click does too, and starts one as well), Shift+click for a range, Ctrl+A for everything in the view, Esc to let go. The toolbar then acts on the selection: Retry, Pause, Resume and Remove (the Delete key too), asking twice when that deletes partial files. In **Failed**, the broom clears every failed download; elsewhere **Clear completed** clears finished downloads, and a finished wrapper with none of its files left.

The ✕ on a row takes the download off the list and leaves its file alone, unless **Settings › Move removed files to the Recycle Bin** is on; then a finished download's file goes to the Recycle Bin. On a download that has started, the ✕ asks for a second click, since its partial file goes too. **Clear completed** only tidies the list.

## Archives

The parts of an archive show as one row, with their combined progress and what needs attention; the chevron opens it to the parts, and a click on it selects them all. Haul knows the forms releases name their parts in, the same JDownloader recognises: `name.part1.rar` (also `name.part01.rar`, `name.p1.rar`), `name.001.rar`, `name.rar` with `name.r00` … `name.r99`, `name.s00` and on, `name.7z.001`, `name.zip.001`, `name.z01` … with `name.zip` last, and `name.001` of any file. Parts of one archive are those in one package; two parts or more make an archive, so `name.rar` alone is a file like any other. When the numbers show a part is missing from the list (`part1` and `part3`, but no `part2`), the row says which, and the archive waits for it.

A release often comes on several hosts, each under names of its own (one host's parts named after an id, say). When two archives have as many parts and every part has the same size to the byte, Haul takes them for the same files: the second becomes more links of the first, so the release downloads once, each part from whichever host serves it, the other standing by when one fails. This needs the parts' sizes before they download, which most hosts give; a host that only gives them as it downloads keeps its copy apart.

Once every part is downloaded, the archive can be extracted: with **Settings › Extract archives when their parts are done** (`auto_extract`) on, that happens by itself as the last part finishes; otherwise, or to try again after it failed, the row's extract button does it. Haul tells RAR (RAR4 and RAR5 volumes), 7-Zip and zip apart by their contents, not their names, so pieces cut by a file splitter (`name.7z.001`, `name.zip.001`) unpack too, and so does a zip split by zip itself into `.z01` pieces. Pieces of a file that is no archive (`movie.mkv.001`, `movie.mkv.002` …) are joined into the file. One archive is unpacked at a time, beside its first part: the row shows _Waiting to extract_, then how far it is, then _Extracted_ or why it failed (a missing part, a password, damage), and the desktop app tells you either way. What the archive holds is unpacked in a hidden folder first and only then moved out, each file or folder under a name nothing has yet (`Release (1)`), so nothing is overwritten and a failure leaves nothing half written. Parts that went to different host folders, or got a numbered name, are gathered for unpacking without being moved. An archive whose parts were all in the download folder before Haul looked does not extract by itself, since Haul downloaded none of it; its button still works. With **Move extracted parts to the Recycle Bin** (`delete_after_extract`) on, the parts go once an archive is unpacked without error, whether it extracted by itself or from its button; the rows stay, done, with no file to show.

An encrypted archive (RAR with its files or its names encrypted, 7-Zip, zip with ZipCrypto or AES) is opened with a password: the one kept with the archive first, then each of **Settings › Archive passwords** (`archive_passwords`, one per line) in turn. When none fits, or there is none, the row says _Needs a password_ and asks for it under the archive, with the reason; the password typed there is kept with the archive (in the queue, never in what the views receive) and tried first from then on, and one that opened it is kept the same way. Every try unpacks into a hidden folder of its own, so a wrong password leaves nothing behind. Diagnostics say how many passwords are set, never which.

## Reporting a problem

**Settings › Diagnostics › Save diagnostics…** saves a report of what Haul is doing: every download and wrapper with its links, state and error and its last 40 events (added, which host it started from, what each host answered, retries), the hosts, the settings, and the end of the log and of the one before it. Account keys, the proxy's user and password, and the part of every link after `#` (where mega.nz keeps its keys) are left out. The log itself is `haul.log` in the data folder (**Show log**, beside **Save diagnostics…**, opens the folder with it picked out), one JSON object per line, kept up to 10 MB with the five files before it; the headless server also prints it to the terminal. When a page the desktop app passes out of sight still wants a person, the log records what it showed (title, frames, buttons) and `webview/chromium/<site>-wants-person.png` in the data folder keeps a picture of the last one per site. To reproduce a problem, switch on **Detailed log** first: the log then records every request, retry and mirror choice, until you switch it off.

## Status bar

The speed and what is downloading, how many links Haul is still unwrapping (wrappers, pages and pastes it opens or passes), and how many downloads and wrappers need you: click that to go to them, in place of a toast for each. Click the speed limit to type a new one, the proxy to switch it on or off or change it, and the clipboard watch (desktop app) to stop it. The download folder is in the left bar, above Hosts: one click opens it.
