# Hosts

How Haul turns each host's link into a file, what it needs from you, and what has been checked against the real host. What happens after that (mirrors, retries, cooldowns) is the same for every host and is in [How downloads behave](downloading.md).

Resolvers live in `crates/haul-core/src/hosts/`; every one is covered by tests against a local stand-in for the host's API (`resolver_tests.rs`), which pins the requests Haul sends and how it reads the answers. Whether a host still answers that way is a separate, live question, tracked in the last column.

| Host                                    | How Haul gets the file                                                                                                                                                                                                      | Needs                                | Checked against the real host                                    |
| --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | ---------------------------------------------------------------- |
| pixeldrain.com, `/u/<id>` and `/l/<id>` | Public API: file info gives name and size up front, so mirrors merge before downloading; lists become one row per file. The current resolver puts files requiring browser interaction (`availability`) under **Needs you**. | Optional `pixeldrain_key`            | Yes, end to end, in the Python prototype; not yet with Haul.     |
| gofile.io, `/d/<id>`                    | Content API with your account token, or a guest token; folders become one row per file. `error-notPremium` (guests blocked from the API) and password-protected folders wait under **Needs you**.                           | Optional `gofile_token`              | Guests saw `error-notPremium` in the prototype.                  |
| buzzheavier.com                         | The download endpoint answers an htmx request with the file's address. No address means the file is gone or wants a browser: **Needs you**.                                                                                 |                                      | The prototype saw "no redirect" on the user's links; unresolved. |
| 1fichier.com                            | With `1fichier_key`, the API's download token. Without, the current free resolver uses **Waiting** for cooldowns and **Needs you** for browser interaction. The affiliate parameter is dropped.                             | Optional `1fichier_key`              | No.                                                              |
| rapidgator.net                          | API v2 with your premium login; the session token is reused and renewed after an error.                                                                                                                                     | `rapidgator_user`, `rapidgator_pass` | No.                                                              |
| nitroflare.com                          | API v2 with your premium key.                                                                                                                                                                                               | `nitroflare_user`, `nitroflare_key`  | No.                                                              |
| mega.nz, mega.co.nz                     | Handed to `megatools dl`, which does MEGA's client-side decryption; progress comes from its output.                                                                                                                         | `megatools` on `PATH` or configured  | No.                                                              |
| fileditchfiles.st                       | Direct link.                                                                                                                                                                                                                |                                      | No.                                                              |
| fileguard.cc                            | A wrapper page: its gate is a proof of work, solved without a person; a one-file page (one link per host) becomes one row with each host as a mirror, the preferred one downloading.                                        |                                      | Live (Oct 16 2026): solved, expanded and downloaded.             |
| filecrypt.cc                            | A wrapper page: the page itself needs a browser, and **Needs you** points at the `.dlc` it offers; a `/DLC/<id>.dlc` link is fetched and read like a dropped container (JDownloader key service).                           |                                      | Live (Oct 16 2026): the gate, and the `.dlc` it offers.          |
| Any other host                          | A HEAD request (or a one-byte GET where HEAD is refused): a file is downloaded as is; a web page waits under **Needs you**; 404, 410 and 5xx fail the mirror; 429 and 503 start a cooldown.                                 |                                      | Local servers only.                                              |
