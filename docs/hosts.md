# Hosts

How Haul turns each host's link into a file, what it needs from you, and what has been checked against the real host. What happens after that (mirrors, retries, cooldowns) is the same for every host and is in [How downloads behave](downloading.md).

Each host Haul knows is one entry of a table in `crates/haul-core/src/hosts/mod.rs` (`KNOWN`): the names it goes by, the code that serves it, the account settings that unlock more, what a free user gets where it was measured (pixeldrain: 5 downloads at once and 6 GB a day at full speed per address, then 1 MiB/s), and whether it says how much an address has left today. The engine and the **Hosts** view read that table rather than host names. Resolvers live in `crates/haul-core/src/hosts/`; every one is covered by tests against a local stand-in for the host's API (`resolver_tests.rs`), which pins the requests Haul sends and how it reads the answers. Whether a host still answers that way is a separate, live question, tracked in the last column.

## Gates, on any site

Most gates in front of a file are the same few products on many sites, so Haul knows each by its own marks in the page (`crates/haul-core/src/hosts/gates.rs`): Cloudflare Turnstile, reCAPTCHA, hCaptcha, an ALTCHA proof of work, Friendly Captcha and GeeTest. On a site Haul has no code for, a page that shows one says so (_site.example shows reCAPTCHA: it wants a browser_) instead of "a web page". Recognising a gate answers nothing by itself: one with no answer goes to you under **Needs you**, as before. The answers Haul has are still each site's own (fileguard's ALTCHA proof of work, filecrypt's checkbox); one written for a kind of gate belongs in that module, for every site that uses it.

A page that lists links and gives an archive password in its text (_Password: abc123_, or quoted when it has spaces) hands that password to the files it lists, as if typed in **Add links**. It's a guess from the words around it, so it is only tried first: a wrong one costs one try before the passwords in Settings, and then you are asked as before.

## The host suite

What Haul does with each kind of site is checked in two halves.

- **The model suite** (`crates/haul-core/tests/suite.rs`) runs on every CI run: one row per kind of site Haul supports, any site through the general way and each host, wrapper and paste with code of its own, against local stand-ins that answer the way that kind of site does. Some rows run in stand-in mode ([debugging](debugging.md#real-sites-stood-in-for)), where a stand-in claims a real site's name as the desktop app's test copies use it. A failing row prints the whole table, so a regression shows beside everything that still works.
- **The release suite** (`crates/haul-core/tests/engine/releases.rs`, `cargo test -p haul-core --test releases`) runs whole releases end to end in stand-in mode: a release page, its paste and a filecrypt container per host, written in a small table language (each source's host, how its table names and sizes its rows, odd rows such as `n/a` or an interstitial's title, a part missing, what its host says when asked). Each case runs in several orders of arrival, also with a restart in the middle of the lookups and after removing everything and adding the page again, and checks the sets, names, links per part, sizes, what is under Failed, the notifications and the friction count. A check that fails today names the task that fixes it and shows as `xfail`; once that work makes it pass, the suite fails with `XPASS` until the mark goes. One row per break in the history of merging sets: copy marks, ID names, rounded sizes, a generic title shared by unrelated sets, `n/a` rows, an interstitial's title, two splits, a part missing from some containers, two unrelated sets with the same title and count, and the acceptance case `standin.py` serves. `--nocapture` prints the table.
- **The live scorecard** (the `haul-scorecard` skill) runs real links through a test copy on the user's machine, when asked: what each host came to, in seconds, and why. Run a second time with `HAUL_GENERIC_ONLY=1`, Haul ignores every site's own code (its table entry, the paste list and page recipes), so the score says what a host Haul has never seen would get. That switch is for measuring, not a setting.

A new host, or an exception found on a real one, becomes a model row, described generically. It is fixed by changing a general rule, not by a branch for one site, and every older row must keep passing.
