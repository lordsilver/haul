# Hosts

How Haul turns each host's link into a file, what it needs from you, and what has been checked against the real host. Resolvers live in `crates/haul-core/src/hosts/`; every one is covered by tests against a local stand-in for the host's API (`resolver_tests.rs`), which pins the requests Haul sends and how it reads the answers. Whether a host still answers that way is a separate, live question, tracked in the last column.

## Behaviour common to every host

- **Names first.** A link whose path names a file joins any row with the same file name as another mirror. A link that hides the name is looked up first (pixeldrain's API, or the first 64 KiB of the page: `Content-Disposition`, `Content-Range`, the page title), and rows for the same name and size merge before anything downloads.
- **Mirror choice.** Among the mirrors whose host has a free slot and no cooldown, the one whose host has measured the best speed per file wins; hosts never tried score high, so each gets a turn.
- **Failures.** A dead link (404, 410) or a refusal fails that mirror at once, and the next mirror takes over; the row shows the host's reason when its answer gives one. A dropped connection, a timeout or an unreachable host is retried on the same mirror with growing pauses (2, 4, 8 seconds and so on), `resume_attempts` times (5 by default), keeping the bytes already downloaded; an attempt that got data in before it stopped starts the count over. After that the mirror counts as failed and the next one resumes the same partial file.
- **Busy hosts.** A 403 while other downloads from the same host are under way means the host takes no more at once. Haul then runs no more from it than were running (shown under **Hosts** as _Takes N at a time_), the refused download waits for a free slot, and the next transfer from that host starts two seconds after one ends. The slot buttons set your own limit and drop the learned one. A link you pasted, or that the in-app browser caught, that stops working asks for a new one instead.
- **Ranking.** Failures lower a host's rank, and each counts half as much every ten minutes, so a host that had a bad moment gets another chance.
- **Failed downloads.** When every mirror has failed, the download waits `retry_failed_minutes` (15 by default) and starts over, up to three times; the row counts down to it.
- **Waiting.** 429 and 503 put the whole host in a cooldown for its `Retry-After` (90 seconds if it gives none).
- **Proxy.** With a proxy configured, every host goes through it until you allow a direct route for that host under **Hosts**. A 403 or 451 through the proxy flags the host; Haul never leaves the proxy on its own.
- **People.** Haul does not solve captchas, skip wait timers or rotate addresses to get around a host's limits. When a host needs a person, the download waits under **Needs you** until you open the page (in the desktop app's own browser, which hands the download back) or paste the final link.
